“Explain your mini project” — Team Script (StyleSense AI)

Use this as a speaking sequence when the examiner asks: “Explain your mini project.” Aim for 2–3 minutes total. Keep it crisp, then go deeper only if asked.

Project: StyleSense AI (ClosetAI)
Android + FastAPI + Firebase/Firestore + Redis + Weather + HF Try-On
Order: Problem → Solution → Architecture → Demo flow → Results → Future

1) One person starts (30–40 seconds) 0:00–0:40

Opening line (say exactly): “Our mini project is StyleSense AI, a mobile fashion assistant that gives personalized outfit recommendations using the user’s profile, wardrobe, and weather context, and it also provides an AI-based virtual try-on preview.”
Problem (2 lines): “Online fashion shopping has too many choices and low confidence due to fit/appearance uncertainty. Existing recommendations often ignore body type, style, weather, and the user’s own wardrobe.”
Solution (2 lines): “We collect onboarding preferences, store profile/wardrobe in Firestore, fetch real products by scraping, rank them with our scoring engine, and optionally generate virtual try-on using a hosted AI model.”

2) Architecture overview (40–50 seconds) 0:40–1:30

  1. Android app (Compose): screens + ViewModels + repositories; uses Retrofit for backend calls.
  2. Backend (FastAPI): endpoints for recommendations, feedback, saved list, wardrobe image upload, try-on proxy.
  3. Firebase Auth + Firestore: UID-based user profile and wardrobe metadata storage.
  4. Redis: caches scraped candidates and feedback-aware ranked lists for fast “Load more”.
  5. External services: OpenWeatherMap for weather, Hugging Face Space (Gradio) for try-on.
If the examiner asks “Where is AI used?”, answer: Try-On is AI (hosted model), and recommendations are scored using a multi-factor ranking engine (rule-based MatchScorer) suitable for cold-start.

3) Demo flow (50–60 seconds) 1:30–2:30

  1. Sign-in: Google sign-in via Firebase.
  2. Onboarding: gender, body type, measurements, skin tone, style/fit, occasion, budget, categories.
  3. Wardrobe: add photo → upload to backend (/api/v1/wardrobe/upload) → store URL + metadata in Firestore.
  4. Recommendations: Home context + Firestore profile → backend scrapes Myntra → ranks → paginates results.
  5. Feedback: like/dislike → stored in Redis → improves next ranking.
  6. Try-on: select garment + selfie → backend calls HF Space → returns base64 image → display + save to history.

4) Results + limitations + future (20–30 seconds) 2:30–3:00

  • Results: working end-to-end system with real product candidates, saved items, and try-on preview integration.
  • Limitations: scraping can break if site HTML changes; try-on latency depends on HF Space cold-start and GPU availability.
  • Future work: add more stores (AJIO/Amazon/H&M), replace rule-based scoring with learning-to-rank, improve try-on quality/latency.

5) Team handoff order (who says what)

  • ABHINEET: App overview + demo steps + try-on UI integration + UX decisions.
  • JAPJIT: Backend endpoints + how caching hash works + uploads + error handling.
  • PRABHSIMRAN: Scraping pipeline + extracted fields + reliability issues + improvements.
  • PANSHUL: Firebase Auth + Firestore schema/rules + why Redis is used for cache/feedback.
  • RATIK: MatchScorer ranking features + weather + feedback-aware reranking + diversification/pagination.
Handoff sentence template: “Now [Name] will explain the [Module] in detail.”

6) If examiner asks “Explain in one line”

One-liner: “StyleSense AI is an Android fashion assistant that recommends real products using profile + wardrobe + weather and provides AI virtual try-on.”
